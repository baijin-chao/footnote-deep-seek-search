## 摘要

向量数据库与传统关系型数据库在检索方式上的本质区别，可以概括为从“精确匹配”到“语义相似”、从“条件筛选”到“近似最近邻搜索”的范式转换。传统关系型数据库以表格存储结构化数据，查询依赖精确匹配或条件筛选，索引用于快速定位满足条件的行[E1][E3]；向量数据库则将文本、图像、音频等非结构化数据经嵌入模型转化为高维向量，通过计算向量间的距离或角度衡量语义相似度，并借助近似最近邻（ANN）算法在海量数据中快速召回“意思相近”的结果[E1][E2][E11]。这一区别不仅是查询语法的差异，更涉及数据表示、索引结构、结果语义与精度权衡的系统性重构。

## 关键发现

1. **数据表示不同**：关系型数据库以表格形式管理结构化数据，非结构化数据难以有效表达[E1]；向量数据库存储的是由 AI 模型生成的高维浮点数组，以数学方式捕捉语义含义[E2][E14]。

2. **检索目标不同**：传统查询基于精确匹配或条件筛选，例如查找某类用户的订单记录[E1]；向量检索基于相似度，返回与查询向量“最接近”的结果，即使两者没有共同关键词[E2]。

3. **索引机制不同**：关系型索引（如 CREATE INDEX）用于快速定位指定行，避免全表扫描[E3]；向量数据库采用 HNSW、IVF 等专门数据结构，以极小精度损失换取数量级的速度提升[E2][E6]。

4. **精度与效率的权衡方式不同**：向量检索存在精确检索（暴力搜索、召回率百分之百但速度慢）与近似检索（速度快、召回率通常 99% 以上）两条路径[E6][E5]，而关系型查询在索引命中时通常返回确定结果。

5. **融合趋势明显**：部分关系型/分析型数据库已在内核中集成向量能力，如 Cloud SQL for MySQL 支持向量列与向量搜索索引[E5]，Apache Doris 将 ANN 检索作为与过滤、连接、聚合并列的基础能力[E8]。

## 分析

两者的本质区别首先体现在**检索语义**上。关系型数据库回答的是“哪些记录满足给定条件”，其正确性由条件表达式严格定义[E1][E3]；向量数据库回答的是“哪些数据在语义上最接近查询”，正确性由距离度量（余弦相似度、欧氏距离、内积等）和召回率共同刻画[E7][E14]。这意味着向量检索天然带有概率性——ANN 以牺牲少量召回率换取性能，而精确 KNN 虽召回率满分却需逐向量比较[E5][E6]。

其次体现在**索引与数据结构的适配对象**上。B 树等关系型索引针对一维有序键值设计，而高维向量空间缺乏这样的全序关系，必须依赖图结构或量化聚类等专用算法[E1][E2]。这也解释了为何传统索引机制无法高效支撑相似性搜索[E1]。

第三，**二者并非替代关系**。证据显示，向量能力正被嵌入现有数据库体系：Cloud SQL 将向量列映射为 VARBINARY 并保留 ACID 事务保证[E5]；Doris 强调向量与结构化过滤相结合的混合查询是其原生优势[E8]；AWS 也将向量存储视为需与现有技术栈集成的组件[E12]。因此更准确的判断是：检索方式的分野正在从“产品类型之争”转向“同一系统内的能力互补”。至于哪条技术路径（专用向量库、关系型扩展、分析型原生）在特定负载下更优，现有证据不足以判断。

## 结论与局限

向量数据库与传统关系型数据库的本质区别在于：前者以高维向量表示数据、以相似度度量定义相关性、以 ANN 索引实现规模化语义召回；后者以结构化表格表示数据、以精确条件定义相关性、以传统索引加速定位[E1][E2][E3][E11]。这一区别源于非结构化数据处理需求与 AI 应用的兴起，并正推动两类系统走向融合[E1][E8][E12]。

本报告的局限在于：证据多来自厂商文档与技术博客，缺乏独立基准测试；各来源对 ANN 召回率、性能指标的具体数值口径不一，现有证据不足以判断不同实现路径的普适优劣；关于混合查询中向量索引与事务一致性的交互细节，证据亦不充分。
