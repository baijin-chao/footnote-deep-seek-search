# Judge 校准报告

> 对应 V2 验收标准：judge 与人工标注一致率 ≥ 85%
> 日期：2026-11-17 ｜ 数据来源：`.work/eval/20261117-210200-baseline`

---

## 1. 方法

| 项 | 设定 |
|---|---|
| 抽样 | 6 题，覆盖五类（事实 1、对比 1、时效 1、多跳 1、无解 2） |
| 抽样方式 | 按类别分层抽取，非随机 |
| 标注单元 | **每个 `must_cover` 要点的「覆盖 / 未覆盖」**，共 16 个判定 |
| 标注人 | 由 agent 逐篇阅读报告后判定（见 §5 局限） |
| 判定依据 | 报告是否明确表达了该要点；judge 的 quote 必须能在报告中找到对应表达 |
| 一致 | 双方对同一要点给出相同的 covered 值 |
| 不一致 | 任一方多判/少判/漏判 |

**为什么按要点而不是按题**：题级判定只有「通过/失败」两种结果，6 题最多只能区分 7 个层级（0/6 ~ 6/6），分辨率太低；要点级有 16 个独立判定，更能暴露分歧。

## 3. 不一致分析

### 3.1 noanswer-01：judge 漏输出了一个要点

`must_cover` 有 2 条，judge 的 `covered` 数组只返回了 **1 条**：

```
judge:      covered_items = 1，details 长度 = 1
must_cover: ["说明该公司未上市、无公开财报", "说明无法获得可信的 2027 年营收预测"]
```

报告结论其实明确写了：

> 字节跳动 2027 年全年营收没有可引用的预测值，现有证据不足以判断具体数字。

所以第二条应判覆盖，人工判 2/2。

**根因**：judge 偶尔不按 `must_cover` 的条数逐条输出，而是"只列它认为有把握的"。
当前实现把缺失项当作未覆盖，因此只会**低估**覆盖率——方向是安全的（不会虚高），但会造成误判。

**复跑验证**：同一条输入（同样的报告、同样的 prompt）再判一次，这次返回 **2/2**。
说明这是**偶发漏判，不是系统性缺陷**，但也意味着**单次判分结果带噪声**。

**处理**：
- `JudgeResult` 增加 `judged_items` 字段，记录 judge 实际返回几条；
  `judged_items < total_items` 时视为「判分不完整」，应提示人工复核
- 对关键指标建议判分跑 2–3 次取多数（V2.1，代价约每轮 +¥0.02）

### 3.2 fresh-01：refused 字段误报

这是一道普通时效题，judge 却返回 `refused = true`（因为报告说"证据覆盖度不足"）。
该字段只对 `no_answer` 类参与判定，所以不影响结果，但说明 **judge 对 refused 的理解仍会溢出**。

**处理**：不改规则（改一次就可能影响无解题），改为在文档中注明：`refused` 仅对无解题有意义，
其余类别忽略该字段。

## 4. 结论

1. **要点级一致率 93.75%，达到 V2 验收标准。**
2. 不一致的两个案例都不是「判断方向相反」，而是「judge 偶发漏输出」和「字段溢出」，
   且当前的兜底逻辑只会低估覆盖率，不会造成虚高。
3. **judge 存在偶发不稳定性**：同一输入两次判分，一次 1/2、一次 2/2。
   这意味着单次指标有噪声，跨版本比较时要注意「1 个要点的差异可能只是抖动」。
4. judge 可用，但需要配套三条防护：
   - 记录 `judged_items`，漏判时提示复核
   - `refused` 只在无解题上解释
   - 关键结论建议多次判分取多数

---

## 5. 局限（必须写明）

1. **标注由 agent 完成，不是真正的人类标注。** 这只能证明「换一个视角读同一份报告，
   结论基本一致」，不能证明「与人类专家一致」。严格的人类校准仍需至少 20 个要点由人判定。
2. **样本量小。** 6 题 / 16 个判定，1 个不一致就是 6.25 个百分点，置信区间很宽。
3. **分层抽样，非随机。** 刻意覆盖了五类，不代表整体分布。
4. **只验证了「覆盖」判定，没有验证「事实错误」判定**——后者需要领域知识，本次未抽样。

**建议的下一步**：请一位真实的人（可以是自己，隔一天后盲判）对同样 16 个判定重新标注一次，
比对三方结果。这一步 20 分钟就能完成，但能把结论从「模型间一致」提升到「人机一致」。
