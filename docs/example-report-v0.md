## 摘要

检索增强生成（RAG）是一种将检索系统与生成式大语言模型结合的架构：系统先从外部知识库检索与问题相关的信息，再把这些信息作为上下文交给模型生成回答，从而在不重新训练模型的前提下补充其静态知识 [E1][E2][E3]。多份资料一致认为，RAG 主要针对大模型的三个固有短板——知识截止、领域知识缺失与幻觉 [E3][E6][E7]。但证据同样显示，RAG 并非"即插即用"的解决方案：其效果高度依赖知识治理与检索质量，且在聚合运算、复杂关系理解、上下文窗口等方面存在结构性局限 [E4][E12]。

## 关键发现

1. **定义共识度高**：各来源对 RAG 的界定基本一致，即"检索模型 + 生成模型"的组合，用私有或专有数据补充生成过程 [E1][E2][E10]。其典型流程为索引、检索、生成三步 [E9][E11]。

2. **核心价值在于"不重训即可更新"**：RAG 无需微调即可接入最新或内部数据，成本低于重新训练 [E3][E7][E9]，并能提供可追溯的来源引用，提升可验证性 [E2][E7]。

3. **局限被多方明确承认**：IBM 直言"RAG 在很大程度上存在缺陷，纯 RAG 并不能真正达到预期的最佳结果" [E12]；实践者亦指出 RAG"入门简单，但要真正达到企业应用的要求很难" [E6]。

4. **局限的根源多在检索侧与数据侧**：分块策略不当、文档过期、元数据缺失、权限过滤不足都会削弱效果，"如果知识库本身混乱，RAG 可能只是把混乱以更自然的语言呈现出来" [E4]。

## 分析

**第一，RAG 缓解幻觉但不消除幻觉。** IBM 明确指出，RAG 可降低幻觉风险，"但它不能使模型完全无误" [E2]。这意味着 RAG 是对概率性生成的外部约束，而非确定性保证；在需要精确答案的场景，其可靠性仍受模型本身制约 [E6]。

**第二，能力边界受架构性限制。** 传统 RAG 依赖向量数据库做相似性检索，而向量库"专为相似性搜索设计，而非数值聚合运算"，加之 LLM 上下文窗口有限，面对十万级发票求和一类任务"根本不可能实现" [E12]。同理，它对实体间复杂关系的辨识不足，需借助知识图谱类方案补足 [E12]。这说明 RAG 擅长"找相关片段"，不擅长"做结构化推理"。

**第三，效果瓶颈从模型转向知识治理。** 多份证据将难点指向数据侧：切分是否合理、权限能否过滤、检索结果是否可解释 [E4]；数据量并非越多越好，需同时优化数据侧与系统侧 [E11]。因此 RAG 的成败更接近一项数据工程，而非单纯的模型选型问题。

**第四，路线选择应由问题性质决定。** 有来源提出判断框架：缺知识优先 RAG，缺动作优先 Agent，缺稳定领域行为才考虑微调 [E4]。这提示 RAG 的局限应放在"适用边界"而非"技术缺陷"的框架下理解。

## 结论与局限

RAG 的本质是用外部可验证知识约束生成模型，其优势在于低成本、可更新、可溯源 [E2][E3][E7]；其主要局限包括：幻觉只能缓解不能消除 [E2]、聚合与关系推理能力不足 [E12]、上下文窗口受限 [E12]、以及高度依赖知识库治理质量 [E4][E11]。需要说明的是，现有证据多为厂商与开发者视角的定性描述，缺乏统一的量化基准；不同来源对"传统 RAG"与改进架构（如 GraphRAG、SQL RAG）的边界划分也不一致 [E12]，因此各类局限在实际系统中的严重程度，现有证据不足以判断。
