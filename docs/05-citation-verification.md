# 引用校验：方法、阈值与局限

> 对应代码：[src/dra/verify.py](../src/dra/verify.py) ｜ 测试：[tests/test_verify.py](../tests/test_verify.py)

---

## 一、要解决什么问题

V0 的报告里，`[E3]` 只是模型自己写的一个编号。它可能：

- 指向一条真实证据，但证据其实不支持这句话（**引用幻觉**）
- 指向一条不存在的编号（**编号幻觉**）
- 只在末尾列出参考来源，正文里根本没引用（**装饰性引用**）

这三种在 LLM 生成的长文里都很常见，而且**看起来完全正常**。面试时最容易被问："你怎么知道引用是真的？"

V1 的答案不是"我在 prompt 里要求它别编"，而是"我在生成之后用程序校验一遍"。

## 二、方法

### 2.1 整体流程

```
报告正文
   │  切句
   ▼
含 [En] 标记的断言
   │  取对应证据的标题+正文+snippet
   ▼
分词（中文 bigram / 英文小写词）
   │
   ▼
覆盖率 = |断言词集 ∩ 证据词集| / |断言词集|
   │
   ├─ ≥ 50%  强支撑
   ├─ 30–50% 弱支撑
   └─ < 30%  未证实
```

### 2.2 为什么中文用字符 bigram

不做分词依赖（jieba 之类），避免引入新的词典和歧义：

- `"检索增强生成"` → `{检索, 索增, 增强, 强生, 生成}`
- 跨词组合也会命中，召回高于精度，正合适——**这一层要做的是粗筛，不是判定**

英文按 `[a-z][a-z0-9_-]+` 取词并小写，与中文集合并。

### 2.3 为什么分三级而不是通过/不通过

第一版是二元的（阈值 50%），实测发现两类误判：

| 情况 | 例子 | 二元判定的问题 |
|---|---|---|
| 改写 | 原文"应当优先评估缺口性质"，报告写"先判断缺的是知识还是行为" | 判为不通过，但语义正确 |
| 综合 | 一句话融合三份文档的结论 | 任何单份文档覆盖率都低 |

于是改成三级：**强支撑 / 弱支撑 / 未证实**。弱支撑不是"错"，而是"需要人看一眼"。报告里直接标注"多为改写或综合表述，需人工复核"。

这比追求一个漂亮的单一数字更诚实，也更接近实际用法——人不看 100 条，只看那 2 条未证实的。

### 2.4 参考来源改为程序生成

模型不再输出参考来源章节（prompt 里明确要求不写），由 `render_references()` 按正文实际出现的编号生成。

好处有两个：
1. 不会出现"列了但没引用"的装饰性条目
2. 编号与 URL 的对应关系由代码保证，不依赖模型记忆

## 三、实测结果

一次真实运行（"RAG 相比微调在哪些场景更划算"）：

| 项 | 值 |
|---|---|
| 证据数 | 12 |
| 引用断言 | 22 处 |
| 强支撑 | 8 处（36%） |
| 弱支撑 | 12 处（55%） |
| 未证实 | 2 处（9%） |
| 落地率（强+弱） | 91% |

两条未证实的原文覆盖率分别是 23% 和 24%，人工看确实是合理改写——**属于误杀**。这也是为什么需要分级和人工复核说明。

## 四、已知局限（必须讲清楚）

1. **只认字面重合**。同义改写、跨语言材料（英文证据支撑中文断言）会低估。
2. **无法识别语义矛盾**。原文"准确率 87%"，报告写"准确率 97%"，词几乎全重合，覆盖率很高——这个方法是发现不了的。
3. **证据长度影响分数**。证据正文越长，常见词越多，覆盖率被抬高。
4. **不做逻辑校验**。把三份互不相关的文档拼成一个因果链，依然能通过。

结论：**它能挡住"完全没来源的编造"，挡不住"细微篡改"**。这不是缺陷掩盖，而是能力边界——V2 会加一层模型校验（用另一个模型判断"这段原文是否支持这句话"），两层互补：

- 词面校验：便宜、确定、可解释，负责粗筛和大批量
- 模型校验：贵、有波动，负责精判

## 五、调参

```ini
# .env
VERIFY_STRONG=0.5
VERIFY_WEAK=0.3
```

- 想让"未证实"更少（宽松）：`VERIFY_WEAK=0.2`
- 想做严格审计（严格）：`VERIFY_STRONG=0.6`、`VERIFY_WEAK=0.4`

调参要基于同一套问题集对比，否则又是凭感觉——这正是 V2 要建评测集的原因。

## 六、面试怎么讲

一句话版本：

> 引用不是让模型自觉，而是在生成后做回填校验：把每个 `[En]` 拿去和原文算词面覆盖率，分级标注；参考来源由程序生成。它能挡住无来源编造，但挡不住细微篡改，所以我下一步要加模型校验。

三个可以主动说的点：

1. **为什么不用 embedding 相似度**——要额外建索引、要额外调用，且对短句不稳；bigram 零依赖、可解释、够用
2. **为什么分三级**——实测二元阈值误杀改写型断言，分级把"错"和"待复核"分开
3. **边界在哪**——数字篡改识别不了，这个要诚实说，并说清楚下一层怎么补
